## 结论

    readPercent = ( Σ bytes(spine[0 .. chapterId]) + offset_in_chapter )
                  / Σ bytes(全 spine)                          → float32

    spine 下标 = chapterId + 1   (epub 的 spine 数组原样, 0 号是 cover)

`offset_in_chapter` = readPosition 里 `##` 后第 4 段的 f3, 章内字节偏移。
f3 = 0 时公式退化成"读完前 N 章"。

## 证据 (4 本书实测, 3 个非零样本)

| 书 | chapterId | f3 | 官方 pct | 本文预测 | 误差 |
|---|---|---|---|---|---|
| 狐的故事 | 5 | 11752 | 0.29326823 | 0.293268246 | +1.6e-8 |
| 路邊的藤井 卷01 | 1 | 0 | 0.009963691 | 0.009963692 | +1e-9 |
| 路邊的藤井 卷03 | 189 | 0 | 0.98467165 | 0.984671678 | +2.8e-8 |
| 路邊的藤井 卷02 | 0 | 0 | 0.0 | (未读, pct 恒 0) | — |

误差量级 = float32 舍入。转成 float32 后**三位全部 bit 级一致**。

**文件字节**算的, 不是按可见字符。这解释了为什么"字符数"永远差一点。

## 副作用 (重要)

`spine[0]` 是 cover, 但**它计入分母**。所以"读完第 1 章"的理论上限
不是 1 章长度 / 全书, 而是 (cover + ch1) / 全书。绝大多数书 cover 很小,
误差可忽略, 但不能假装它不存在。

## totalCount

`totalCount` = spine 长度 - 1 (8 / 194 / 192 / 192 / 590 全中)。
= "可计为正文的文档数", cover 不算。掌阅自己填的, 与 spine 对齐。

## readPosition 格式

    <pre>$##<f0>-<f1>-<f2>-<f3>-<f4>##$

    pre = "<chapterId+1>_0_0"
    f0  = 3        官方恒为 3 (我们伪造的写 0 → app 可能不认)
    f1  = 0
    f2  = <chapterId+1>   (与 pre 冗余)
    f3  = 章内字节偏移       ← 喂给 readPercent 的那个
    f4  = 0

## 推论: 章内偏移怎么来

掌阅 app 停在章节开头 → f3 = 0。若想精确到页, f3 就是当前页在文件里的
字节位置。我们只能写 0 (我们没有章节正文, 书是整本 EPUB 传书)。
误差上界 = 一章长度 / 全书, 剑来 590 章约 0.2%, 远小于 200 字符目标。

是伪兼容。实测三本 app 写的记录全是 0-1 比例, 唯一的 "100" 是
**我们自己**用 kavita-bridge 写的 (剑来)。所以: 读 app 数据时直接
float() 即可, 分支可以删。
